# 第 6 课：存储型 XSS —— 毒不下在杯子里，下在井里

- **日期**：2026-11-01（补记）
- **靶场**：`/tmp/xss2.py`（留言板，留言存进 SQLite）
- **状态**：✅ 完整闭环
- **一句话总结**：代码不是挂在网址上，是**存进数据库**——谁打开页面谁中，不用骗人点链接。

## 跟第 5 课的区别

| | 第 5 课（反射型） | 第 6 课（存储型） |
|---|---|---|
| 毒在哪 | 网址的 `?m=` 里 | **数据库里** |
| 谁中招 | 点了那条链接的人 | **所有打开页面的人** |
| 要不要骗人点 | 要 | **不用** |

## 我做了什么

靶场换成了一个带表单的留言板：名字 + 留言，提交后存进数据库，再取出来显示。

第一步，先正常发一条「今天学了存储型」——列表里正常显示。

第二步，再发一条，留言内容填：

```
<script>alert(1)</script>
```

**注意：这次连网址都不用改，正常打字就行。**

## 结果

- 提交之后**弹窗**
- **刷新页面，还弹**
- **新开一个标签页打开首页，照样弹** ← 这一步最要命

那个新开的标签，跟刚才那条留言没有任何关系，但它一打开首页就中招了。

**因为毒已经在数据库里了，页面每次渲染都会把它取出来执行。**

## 修好它

关键改动：**取出来显示的时候才转义。**

```python
from html import escape
...
items = "".join("<li><b>%s</b>：%s</li>" % (escape(n), escape(b)) for n, b in rows)
```

改完再发一条同样的 `<script>alert(1)</script>` —— **不弹了，显示成文字。**

## 学到的东西（我自己的话）

1. **存储型不用骗人点链接。**
   攻击者只要在评论区发一条带代码的留言，然后走人 —— 之后每个来看这个页面的人都中招。

2. **一次投毒，全站中招。**
   反射型是一次骗一个，存储型是往水井里下毒。

3. **转义要放在「输出」那一步，不是「存进去」的时候。**
   数据库里应该存**原文**。因为这份数据以后可能还要给别的程序看、导出、走接口 ——
   你在存的时候就改了它，数据就脏了。

4. **加了转义之后，数据库里历史留下的毒，也会安全地显示成文字**（不执行）。

5. 根还是那个根：**数据被当成了代码。**

## 卡在哪

- 一开始没转过弯：以为「每次多弹一次」是又被打了一次，
  其实是**存了几条就弹几次**。
- 差点以为转义应该放在「存进数据库之前」—— 被纠正了。
  **入口存原文，出口按场景转义。**
