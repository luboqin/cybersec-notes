# 第 5 课：XSS —— 让别人的浏览器替我干活

- **日期**：2026-10-29
- **靶场**：`/tmp/xss.py`（留言板，网址 `?m=` 参数）
- **状态**：✅ 完整闭环（打穿 → 看懂 → 修好 → 再打不进去）
- **一句话总结**：不用黑服务器。把毒链接撒出去，谁点谁替我干活。

## 我想干什么

前四课都是在登录框、在网址参数里动手脚。这一课想试试：
**把"代码"本身塞进去，会发生什么？**

## 我做了什么

第一步，先正常看一眼这个留言板：

```
http://127.0.0.1:8000/?m=你好
```

页面显示「你好」—— 正常。

第二步，往同一个地方塞一段代码：

```
http://127.0.0.1:8000/?m=<script>alert(1)</script>
```

（如果浏览器把尖括号吞了，就用编码版）

```
http://127.0.0.1:8000/?m=%3Cscript%3Ealert(1)%3C/script%3E
```

## 结果

**浏览器弹了一个 `1`。**

按 `Ctrl+U` 看网页源码，`<script>alert(1)</script>` **明明白白在源码里**；
但页面上**不显示**。

为什么？因为浏览器把它当**代码**跑了，没当文字显示。

服务器那边打出来的是：

```
页面里塞进去的原文 >>> <script>alert(1)</script>
```

**一个字的过滤都没有，原样塞进网页。**

## 修好，再打一次

加一行 `from html import escape`，把 `% m` 改成 `% escape(m)`。

同样的链接再打一次：

- **不弹窗了**
- 页面上直接显示成文字：`<script>alert(1)</script>`

再换个标签试一次，看是不是"只拦 script"：

```
http://127.0.0.1:8000/?m=%3Cimg%20src%3Dx%20onerror%3Dalert(1)%3E
```

**还是不弹。**

结论：**不是只拦 `script`，是所有标签一律转义。**

## 学到的东西（我自己的话）

1. **原来根本不用黑服务器。**
   网页是给浏览器看的，在网页上做手脚，就能让浏览器替我干活。

2. **点毒链接的人，都是替罪羊。**
   我可以在他的浏览器里、用他的身份干坏事，自己自始至终不露面。

3. **服务器不是"被绕开"，是"被利用"。**
   它把代码原样发给了每个访问者 —— 它全程正常干活、压根不知道发生了什么，
   但**投递的责任在它身上**。所以锅不能全甩给受害者，漏洞在服务器。

4. **不露面 ≠ 抓不到。**
   攻击者不出现是真的，但**毒链接总得发出去** —— 发链接的账号、IP、群记录，就是线索。
   所以是「难直接定位」，不是「绝对抓不到」。

5. **转义是"替换"，不是"拦截"。**
   `<` 一律换成 `&lt;`，不是"看见坏字就拦住"。
   所以我一开始想的"换个开头、换个标签就能绕过去"是错的 —— **每个尖括号它都换。**

6. **浏览器是厨师，网页是菜谱。**
   菜谱不会做菜，是厨师照着做。代码写在网页里，执行在浏览器里。

7. **身份不是偷的，是"在哪跑"自动发的。**
   代码在哪个网站的页面里跑，浏览器就发那个网站的"工牌"，
   它就能碰那个网站的东西（这叫**同源策略**）。

## 卡在哪

- **名字说错过一次**：我一开始管它叫「命令注入」。
  其实 XSS 打的是**浏览器**，命令注入打的是**服务器的 shell**，不是一回事。
  三种对照：SQL 注入 → 数据库 / XSS → 浏览器 / 命令注入 → 服务器 shell。

- **一度以为转义能绕**：想着"我把 `<` 换个位置不就行了"。
  想错了 —— 转义不是检查开头，是**每一个都换**。
