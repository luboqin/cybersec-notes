# 第 4 课：GET 参数也是输入 + UNION 拖库

- **日期**：2026-10-10
- **靶场**：`/tmp/search.py`（搜索页，`?q=` 参数）
- **状态**：⚠️ **未完成**

## 已经做成的

把网址改成：

```
http://127.0.0.1:8000/?q='\''
```

服务器报错页回显：

```sql
SELECT id, title FROM articles WHERE title LIKE '%'\''%'\''
```

**一个单引号就把句子撕开了** —— 证明我填的字被当成**句子的一部分**在读。

## 还欠着的两关

### 关一：让搜索变成"全都给我"

补全引号让 WHERE 永远为真，**并把末尾多出来的 `%'\''` 注释掉**。
成了会一次列出三条文章。

### 关二：把 users 表拖出来（UNION）

土话版：**你不让我看 users 表？那我就让搜索结果里顺便把它列出来。**

三步：

1. **先探列数**（UNION 前后列数必须一样）
   - `?q=x'\'' UNION SELECT 1 --` → 预期报错
   - `?q=x'\'' UNION SELECT 1,2 --` → 通了，说明原文是 **2 列**
2. 把 `1,2` 换成 `user, pass`
3. 成了会冒出三行 `[admin] Sup3rS3cret!!` ……

## 顺手学到的两个

1. **报错本身就是情报** —— SQL 报错会把句子结构漏给你，这叫「**报错注入**」
2. **把错误直接显示在页面上是另一个毛病** —— 等于给攻击者递地图
