# 第 3 课：黑名单绕过 —— 努力防了 ≠ 防住了

- **日期**：2026-10-10
- **靶场**：`/tmp/maybe.py`（加了黑名单 `["--","or","select","union","drop","insert","update"]`）
- **一句话总结**：**黑名单必输** —— 它既防不住坏人，又误伤好人。

## 我试了三次

| 第几次 | 我填的 | 结果 |
|---|---|---|
| 1 | `admin'\'' --` | 「检测到非法字符，已拦截！」 |
| 2 | `'\''OR'\''1'\''='\''1` | sqlite 报 `unrecognized token` —— **引号没配对** |
| 3 | **`x'\'' OR '\''1'\''='\''1`** | ✅ **进去了！** |

第 3 次服务器实际执行：

```sql
SELECT * FROM users WHERE user='\''admin'\'' AND pass='\''x'\'' OR '\''1'\''='\''1'
```

## 为什么必进

把条件掰成两半：

- `（user='\''admin'\'' AND pass='\''x'\''）` → **假**
- `（'\''1'\''='\''1'\''）` → **真**

**假 OR 真 = 真**，整句成立。

> 我不是猜到了密码，我是把**"判断条件"本身改写了**。

那个 `x` 是**随便编的假密码**，只是让开头那个引号有东西可闭合。

## 黑名单为什么没拦住（三宗罪）

1. 名单里写的是**小写 `or`**，但 **SQL 不认大小写** —— 我一个字没改，只按住了 Shift
2. **穷举必输**：得把所有坏写法列全，攻击者只要找到**一种没列进去的**就赢
3. **还误伤好人**：谁的密码里带 `or` 三个字母，自家防护先把人挡在门外

## 引号为什么必须配对

```
pass='        ← 开头这个引号是服务器给的
      ↑ 中间是我填的
                        '\''   ← 结尾这个引号也是服务器给的
```

**末尾千万别自己再补一个引号** —— 那一半服务器替你补。要的是「**跳出去**」。

> 判断能不能注入、怎么注入，靠的就是：**我填的字落在句子的哪儿。**
