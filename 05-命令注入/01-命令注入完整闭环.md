- **状态**：✅ 完整闭环（打穿 → 看懂 → 修好 → 再打不进去）

## 我想干什么

前六课打的是**数据库**和**浏览器**。这一课想看：

> 如果网站会「执行系统命令」，能不能让它执行**我的**命令？

## 我做了什么

靶场是个「ping 工具」—— 填个 IP，服务器去 ping 它。

第一步，正常用：填 `127.0.0.1` → 正常 ping 出结果。

第二步，试试能不能「顺便」再干点别的：

```
127.0.0.1 ; id
```

**结果：服务器把 `id` 跑了**，页面上多出来一行 `uid=...`。

## 越试越离谱

```
127.0.0.1 ; whoami
127.0.0.1 ; ls /
```

`ls /` 把**整台机器的根目录**全列出来了。

**不是网站，是这台电脑。**

## 为什么能这样

代码是这么写的：

```python
cmd = "ping -c 2 " + ip
subprocess.run(cmd, shell=True)
```

三件事叠在一起：

1. 你填的东西被**直接拼进命令字符串**
2. `shell=True` 让 **shell（传话人）**去解析这句话
3. shell 看到 `;`，就知道「这是两条命令，都要跑」

所以：

- 填 `127.0.0.1` → 跑 `ping -c 2 127.0.0.1`
- 填 `127.0.0.1 ; id` → 跑 `ping -c 2 127.0.0.1`，**然后**跑 `id`

## 修好它

```python
subprocess.run(["ping", "-c", "2", ip])
```

改动：**一根字符串 → 一个列表，而且不再交给 shell。**

用点菜打个比方：
> 原来是把单子递给**服务员**（shell），他看懂分号 = 两道菜。
> 现在是直接把单子递给 **ping 这个厨师**，他只会做 ping，`; id` 他当成菜名的一部分。

再打一次 `127.0.0.1 ; id`：

```
ping: 127.0.0.1 ; id: Name or service not known
```

**ping 把整串当成一个地址名去查，查不到 → 报错。**

分号变成了**普通字符**，`id` 没被执行。

## 学到的东西（我自己的话）

1. **shell 是传话人，ping 是个厨师。** 洞不在 ping 身上，在「谁去解释那句话」上。

2. **交给 shell，分号就是指令；直接递给程序，分号只是字符。**

3. **修好了不是「没反应」，是「变成一个普通错误」。**
   修之前是**多跑了一条命令**，修之后是 **ping 说地址不认识** —— 后者安全。

4. **命令注入比前两种都严重：**

   | 漏洞 | 你能碰到哪 |
   |---|---|
   | SQL 注入 | 一个**数据库** |
   | XSS | 一个人的**浏览器** |
   | **命令注入** | **整台服务器** |

5. **同一个根，第三次了：别把数据拼进命令。**
   - SQL 注入 → 用 `?` 占位符分开
   - 命令注入 → 用**列表参数**分开
